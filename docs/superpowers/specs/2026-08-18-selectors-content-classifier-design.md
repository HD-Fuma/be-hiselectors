# 셀렉터스 콘텐츠 판별기 설계

## 1. 목적

SNS 게시물의 텍스트에서 셀렉터스 관련 증거를 추출해 다음 세 상태로 분류한다.

- `CONFIRMED`: 셀렉터스 콘텐츠임을 뒷받침하는 결정적 증거가 있음
- `REVIEW_REQUIRED`: 결정적 증거는 없지만 사람이 우선 검토할 만한 정황이 있음
- `NOT_SELECTORS`: 현재 텍스트만으로는 셀렉터스 관련 근거가 부족함

기존 수집 서비스와의 호환성을 위해 `isSelectorsContent(RawContent)`는 유지하며,
새 `classify(RawContent)` 결과가 `CONFIRMED`일 때만 `true`를 반환한다. DB 구조와 저장 정책은
이번 변경 범위에 포함하지 않는다.

## 2. 설계 원칙

1. 결정적 규칙과 추정 점수를 분리한다. 약한 신호 여러 개가 우연히 더해져 자동 확정되는 것을 막는다.
2. 본인 코드만 인정하지 않는다. 정상 형식의 다른 셀렉터스 코드도 관련 콘텐츠로 수집한다.
3. 더현대 공용 상품 URL만으로는 확정하지 않는다. 일반 상품 공유와 구분할 수 없기 때문이다.
4. 해시태그 규칙은 일반 문자열이 아니라 실제 `#해시태그` 토큰에만 적용한다.
5. 판정 결과에 점수와 근거를 함께 반환해 결과를 설명하고 규칙을 재현할 수 있게 한다.
6. 판별 규칙 버전을 결과에 포함해 향후 규칙 변경을 추적할 수 있게 한다.

## 3. 판정 흐름

### 3.1 텍스트 정규화

- `RawContent.texts`를 줄바꿈으로 결합한 값을 사용한다.
- Unicode NFKC 정규화를 적용한다.
- URL 호스트와 영문 키워드는 대소문자를 구분하지 않는다.
- URL은 `http://` 또는 `https://`로 시작하는 문자열만 추출한 뒤 URI로 파싱한다.
- 후행 문장부호 `. , ! ; : ) ' \" ] } >`는 URL에서 반복 제거한다.
- 판정용 URL은 user-info가 없어야 하며, 포트가 없거나 스킴의 기본 포트(`80`, `443`)여야 한다.
- 호스트는 정확히 `hi.thehyundai.com`이어야 한다. 하위·유사 호스트는 인정하지 않는다.
- 경로와 쿼리는 디코딩하지 않은 raw 값을 검사한다. 판정에 사용하는 경로 또는 `ptrsRefCd` raw 값에
  `%` 인코딩이 있으면 해당 결정적 규칙으로 인정하지 않는다. 다른 쿼리 매개변수의 인코딩은 허용한다.
- 해시태그는 `#` 뒤의 한글·영문·숫자·밑줄 토큰으로 추출한다.

### 3.2 결정적 확정 규칙

다음 중 하나라도 충족하면 `CONFIRMED`다.

1. URL 밖의 일반 텍스트에 정상 형식 레퍼럴 코드가 존재한다.
   - 초기 형식: 대소문자 무시 ASCII `RC` + ASCII 숫자 9자리 + `T`
   - 예: `RC000005105T`
   - 다른 셀렉터의 코드도 인정한다.
   - URL 인코딩되거나 형식이 깨진 코드는 인정하지 않는다.
   - 앞뒤가 Unicode 문자·숫자·밑줄이면 코드로 인정하지 않는다.
   - NFKC 정규화로 전각 영문·숫자가 ASCII로 바뀐 경우는 정규화된 형식으로 검사한다.
   - 악성·유사 호스트 URL 안의 코드 문자열은 단독 코드 규칙으로 승격하지 않는다.
2. 정확한 `hi.thehyundai.com` 상품 URL의 `ptrsRefCd` 쿼리 값이 정상 레퍼럴 코드다.
   - 경로는 `/product/{상품 식별자}` 또는 뒤에 `/`가 붙은 형태만 허용한다.
   - 상품 식별자는 ASCII 영문·숫자·밑줄·하이픈 1~100자다.
   - 쿼리 이름은 대소문자를 구분하지 않지만 raw 값은 URL 디코딩하지 않는다.
   - `ptrsRefCd`가 중복되면 모호한 URL로 보고 결정적 근거에서 제외한다.
3. 정확한 `hi.thehyundai.com` 호스트의 셀렉터스 전용 경로다.
   - `/sellectors/manage/shop/{RC코드}`
   - `/sellectors/manage/shop/{RC코드}/{그룹 식별자}`
   - `/sellectors/{샵 또는 그룹 식별자}`
   - RC코드는 위 정상 형식, 나머지 식별자는 ASCII 영문·숫자·밑줄·하이픈 1~100자다.
   - 선택적인 마지막 `/`만 허용한다. 빈 식별자, 추가 경로, `.`·`..`, 인코딩 경로는 거부한다.
4. 실제 해시태그 중 `%더현대%` 토큰과 정확한 `#셀렉터스` 토큰이 각각 존재한다.
   - `#더현대서울 #셀렉터스`: 확정
   - `#더현대 #셀렉터스`: 확정
   - `#더현대서울`: 미확정
   - `#셀렉터스`: 미확정
   - 일반 문장 `더현대 셀렉터스`: 미확정
   - 단일 태그 `#더현대셀렉터스`: 미확정

공용 상품 URL `/product/{상품번호}`는 레퍼럴 코드가 없으면 확정 근거가 아니다.

### 3.3 검토 점수

결정적 규칙 여부와 관계없이 다음 소프트 점수를 합산한다. 결정적 규칙이 있으면 결과는 항상
`CONFIRMED`이고 점수는 분석·설명 용도로만 남는다.

| 근거 | 점수 | 비고 |
| --- | ---: | --- |
| `더현대 셀렉터스` 또는 `#더현대셀렉터스` 명시 | +5 | 일반 셀렉터스 명칭과 중복 가산하지 않음 |
| 독립된 `셀렉터스` 또는 `Selectors` 명칭 | +4 | `셀렉터스몰` 같은 다른 단어의 부분문자열은 제외 |
| 셀렉터스샵·셀렉터스 샵 명시 | +4 | 위 명칭 신호와 중복 가산하지 않음 |
| 문법이 유효한 더현대 공용 상품 URL | +3 | 추천 코드가 없으면 URL만으로 확정 금지 |
| 경제적 이해관계 표시 | +1 | 광고·협찬·제휴·판매수수료 등 |
| 구매 전환 문구 | +1 | 프로필 링크·구매·주문·쿠폰 등 |
| 더현대 언급 또는 관련 해시태그 | +1 | 단독으로 검토 대상이 되지 않음 |

- 6점 이상: 강한 검토 후보
- 3~5점: 일반 검토 후보
- 0~2점: 비대상

두 검토 구간은 모두 `REVIEW_REQUIRED`로 반환하고, 점수로 우선순위를 구분한다. 초기 버전에서는
검토 점수만으로 `CONFIRMED`에 승격하지 않는다.

활성 신호의 문법은 규칙 버전에 고정한다.

- 브랜드 결합 명칭: 공백을 허용한 `더현대 셀렉터스` 또는 정확한 `#더현대셀렉터스`
- 독립 명칭: Unicode 문자·숫자·밑줄로 둘러싸이지 않은 `셀렉터스`, 대소문자를 무시한 `Selectors`
- 샵 명칭: `셀렉터스`와 `샵` 사이의 공백만 허용한다.
- 경제관계 사전: 정확한 해시태그 `#광고`, `#협찬`, `#ad`; 또는 정규화된 본문의 고정 구문
  `유료광고`, `유료 광고`, `광고입니다`, `협찬받아`, `제휴 링크`, `판매 수수료`,
  `paid partnership`, `paid link`
- CTA 사전: 정규화된 본문의 고정 구문 `프로필 링크`, `링크 확인`, `링크 클릭`, `구매하기`,
  `지금 구매`, `바로 구매`, `구매 링크`, `주문하기`, `지금 주문`, `예약하기`, `쿠폰`, `할인 코드`,
  `DM 문의`
- 더현대 신호: `더현대`, `현대백화점`, 대소문자를 무시한 독립 구문 `the hyundai`, 또는 `더현대`를
  포함한 실제 해시태그

브랜드 결합 명칭·독립 명칭·샵 명칭은 가장 높은 한 항목만 가산한다. 다른 종류의 신호는 각 종류별로
한 번만 가산한다. 상품 카탈로그 일치와 승인 대행사 태그는 필요한 컨텍스트가 `RawContent`에 없으므로
v1 점수·근거 enum에서 제외하고 후속 확장으로만 남긴다.

해시태그 사전은 추출된 태그 전체가 사전 단어와 같을 때만 일치한다. 따라서 `#광고주`, `#협찬사`,
`#advice`는 광고 신호가 아니다. 나머지 고정 구문 사전은 NFKC 정규화와 영문 대소문자 정규화 후
literal substring으로 탐지한다. CTA 사전에 단독 `구매`, `주문`, `예약`을 넣지 않으므로 `구매력`,
`주문진`, `예약어` 같은 우연한 부분문자열은 점수를 얻지 않는다. 같은 사전 구문이 반복돼도 종류별
점수는 한 번만 부여한다.

공용 상품 URL은 정확한 호스트와 `/product/{상품 식별자}` 경로가 유효하면 항상
`PUBLIC_PRODUCT_URL` 근거와 3점을 얻는다. `ptrsRefCd`가 없거나, 값이 잘못됐거나, 인코딩됐거나,
중복되어 결정적 URL 규칙에서 제외돼도 공용 상품 URL 점수는 유지한다. 반면 경로 자체가 인코딩됐거나
문법이 잘못된 URL은 공용 상품 URL 점수도 얻지 못한다.

대표 경계 예시는 다음과 같다.

| 텍스트 신호 | 점수 | 결과 |
| --- | ---: | --- |
| `더현대` + `#광고` | 2 | 비대상 |
| `더현대` + `#광고` + `프로필 링크` | 3 | 일반 검토 |
| `더현대 셀렉터스` | 6 | 강한 검토 |
| 독립 `셀렉터스` + `더현대` | 5 | 일반 검토 |
| 코드 없는 공용 상품 URL + `더현대` + `#광고` + `구매하기` | 6 | 강한 검토 |

## 4. 반환 모델

`SelectorsContentClassification`은 다음 정보를 가진 불변 값 객체다.

- `decision`: `CONFIRMED`, `REVIEW_REQUIRED`, `NOT_SELECTORS`
- `score`: 결정적 규칙을 제외한 검토 점수
- `reviewTier`: `STRONG`, `NORMAL`, `NONE`
- `evidence`: 탐지된 근거 enum의 선언 순서대로 정렬된 불변 집합
- `referralCodes`: 대문자로 정규화하고 사전순으로 정렬한 불변 목록
- `matchedUrls`: 본문에서 추출·후행 문장부호 제거 후 사전순으로 정렬한 불변 목록
- `ruleVersion`: 초기값 `selectors-text-v1`

`isSelectorsContent`는 `classification.decision() == CONFIRMED`의 호환용 래퍼다.

결과 불변식은 다음과 같다.

- 결정적 규칙 여부와 무관하게 모든 활성 소프트 신호를 계산하고 `score`와 `evidence`에 남긴다.
- `CONFIRMED`: `reviewTier=NONE`. 결정적 근거가 하나 이상 존재한다.
- `REVIEW_REQUIRED`: 결정적 근거가 없고 점수가 3 이상이다. 6점 이상은 `STRONG`, 그 외는 `NORMAL`이다.
- `NOT_SELECTORS`: 결정적 근거가 없고 점수가 0~2다. `reviewTier=NONE`이다.
- `evidence` enum은 `REFERRAL_CODE`, `PRODUCT_URL_WITH_REFERRAL`, `SELECTORS_SHOP_URL`,
  `DESIGNATED_HASHTAG_PAIR`, `SELECTORS_BRAND_PHRASE`, `SELECTORS_NAME`, `SELECTORS_SHOP_NAME`,
  `PUBLIC_PRODUCT_URL`, `ECONOMIC_DISCLOSURE`, `PURCHASE_CTA`, `THE_HYUNDAI_MENTION`으로 고정한다.
- 결정적 URL 안의 코드는 URL 근거와 코드 근거를 모두 남기되, `score`에는 영향을 주지 않는다.

## 5. 오류와 경계 처리

- `RawContent`가 `null`이면 명확한 `IllegalArgumentException`을 던진다.
- 빈 텍스트는 `NOT_SELECTORS`, 0점으로 반환한다.
- 악성 유사 호스트(`evilhi.thehyundai.com`)는 인정하지 않는다.
- 악성 URL 안의 정상 코드 문자열도 단독 코드로 승격하지 않는다.
- URL 인코딩으로 코드 형식을 우회한 값은 인정하지 않는다.
- URI 파싱 실패, 지원하지 않는 스킴, user-info, 비기본 포트는 해당 URL 근거만 무시하고 나머지 본문
  판정을 계속한다.
- 같은 근거가 여러 번 반복돼도 한 번만 점수를 부여한다.
- 같은 레퍼럴 코드나 URL은 결과에서 중복 제거한다.
- 결과 집합은 외부에서 변경할 수 없게 복사한다.

## 5.1 기존 동작의 의도적 변경

- URL 밖의 정상 레퍼럴 코드 단독 게시물은 기존 `false`에서 `true`로 바뀐다.
- 일반 문장에 `더현대`와 `셀렉터스`가 함께 있는 게시물은 기존 `true`에서 `false`로 바뀌며,
  `REVIEW_REQUIRED` 결과로만 남는다.
- 코드 없는 공용 상품 URL은 `REVIEW_REQUIRED`이고 `isSelectorsContent`는 `false`다.
- 두 실제 해시태그 조건 또는 전용 샵 경로는 `true`다.

기존 호출자는 메서드 변경 없이 컴파일되지만 위 의미 변화에 맞춰 단위 테스트를 교체해야 한다.

## 5.2 검토 후보의 현재 통합 범위

`ContentCollectionService`는 현재 `isSelectorsContent == true`인 콘텐츠만 DB에 저장한다. 따라서 v1에서
`REVIEW_REQUIRED`는 의도적으로 DB에 저장되지 않는다. 새 `classify` API는 오프라인 표본 평가와 향후
검토 큐 소비자가 점수·근거를 사용할 수 있게 만드는 계약이다. 검토 후보를 영속화하려면 별도 상태와
검토 이력 설계가 필요하므로 이번 무DB 변경 범위에 포함하지 않는다.

## 6. 데이터 근거

2026-08-18 안전 수집 표본 1,439건에 초기 탐지식을 적용한 결과다.

| 신호 | 건수 | 비율 |
| --- | ---: | ---: |
| 정상 형식 레퍼럴 코드 | 1 | 0.07% |
| 셀렉터스 전용 경로 | 1 | 0.07% |
| 셀렉터스·Selectors 명칭 | 4 | 0.28% |
| 더현대 언급 | 54 | 3.75% |
| 광고·협찬·제휴 표시 | 430 | 29.88% |
| 구매 전환 문구 | 41 | 2.85% |

결정적 규칙의 합집합은 1건이었다. 광고·협찬 표시는 약 3분의 1에서 발견되어 단독 확정 근거로
사용하기 어렵다. 이 결과는 사용자 제공 태그 계정 58개의 첫 페이지 표본이므로 전체 모집단 비율로
일반화하지 않는다.

## 7. 신뢰도 및 임계값 검증

사람 라벨의 재현성과 알고리즘 성능을 분리해 평가한다.

1. 현재 500건 표본을 점수 구간별로 층화하고, 결정적 규칙 표본은 전수 포함한다.
2. 두 판정자가 독립적으로 `해당/비해당`과 근거를 기록한다.
3. 두 명이면 Cohen's kappa, 세 명 이상 또는 결측 허용이면 Krippendorff's alpha를 계산한다.
4. `κ 또는 α >= 0.8`일 때 코드북이 안정적이라고 본다. 미달이면 불일치 항목을 분석해 정의를
   고치고 새 검증 표본으로 다시 측정한다.
5. 합의된 정답과 분류 결과는 정밀도, 재현율, F1, 혼동행렬로 평가한다.
6. 점수 임계값 후보 3~8점을 층화 교차검증 또는 부트스트랩으로 비교한다. 클래스 불균형 때문에
   정확도만 사용하지 않는다.

`0.8`은 콘텐츠 점수 임계값이 아니라 판정자 간 신뢰도 기준이다.

## 8. 타사 운영 방식에서 얻는 원칙

- Amazon Associates는 Associate ID와 Tracking ID가 포함된 특별 링크로 유입과 성과를 연결한다.
- 네이버 브랜드 커넥트는 활동 채널 인증과 상품별 전용 링크 발급을 중심으로 운영한다.
- YouTube Shopping은 플랫폼 내부 상품 태그와 분석 데이터를 관리한다.
- impact.com은 캠페인 과업, 제출 콘텐츠, 추적 링크와 전환 데이터를 연결한다.

공통점은 자유 텍스트보다 플랫폼이 발급하거나 관리하는 식별자를 강한 근거로 사용한다는 것이다.
따라서 셀렉터스도 레퍼럴 코드·전용 경로를 최우선으로 보고, 일반 문구는 검토 점수로만 사용한다.

## 9. 별도 후속 범위

다음 항목은 셀렉터스 관련 여부와 독립된 판정 축으로 분리한다.

- 광고 표기 준수 여부
- 영상 최소 길이
- 욕설·유해 표현
- 이미지·영상·음성에만 존재하는 표시
- 게시물 텍스트 변경 해시 및 미디어 개수·식별자 변경
- 클릭·구매 전환과 게시물·상품의 추적 ID 연결

위반 여부가 셀렉터스 관련 여부를 바꾸지는 않는다. 먼저 관련 콘텐츠를 식별한 후 별도의 위반 검사기가
진단해야 한다.

## 10. 테스트 범위

- 정상·다른 사람 레퍼럴 코드 단독 확정
- `XRC000005105TY`, 뒤에 Unicode 문자·숫자·밑줄이 붙은 코드 거부
- 형식이 깨진 코드와 URL 인코딩 코드 거부
- 정상 코드가 악성·유사 호스트 URL 안에만 있는 경우 거부
- 추천 코드가 있는 공용 상품 URL 확정
- 추천 코드가 있는 공용 상품 URL은 `PRODUCT_URL_WITH_REFERRAL`, `REFERRAL_CODE`,
  `PUBLIC_PRODUCT_URL` 근거와 soft score 3을 함께 반환
- 추천 코드 없는 공용 상품 URL은 검토 후보
- 무관한 쿼리 매개변수만 인코딩된 정상 추천 URL은 확정
- 잘못된·인코딩된·중복 `ptrsRefCd`의 유효한 공용 상품 URL은 확정하지 않되 3점 검토 후보
- 전용 샵·그룹 URL 확정
- 빈 식별자, 추가 세그먼트, 점 세그먼트, 인코딩 경로 거부
- 정확한 호스트 경계와 유사 호스트 거부
- URL user-info, 비기본 포트, 잘못된 URI, 중복 `ptrsRefCd` 거부
- 두 종류 해시태그 동시 존재 확정
- 일반 문장, 한쪽 해시태그, 단일 결합 해시태그는 미확정
- 중복 신호 단일 가산
- 브랜드 결합·독립 명칭·샵 명칭의 중복 가산 방지
- `#광고`·`#ad`는 탐지하고 `#광고주`·`#advice`는 거부
- 고정 CTA는 탐지하고 `구매력`·`주문진` 같은 우연한 부분문자열은 거부
- 검토 점수 경계 2·3·5·6점
- 확정 결과에서도 soft score를 계산하되 `reviewTier=NONE`인 불변식
- 빈 텍스트, 여러 텍스트 분산 신호, 대소문자 및 Unicode 정규화
- 기존 `isSelectorsContent`의 확정 전용 하위 호환
- 서비스가 `REVIEW_REQUIRED`를 기존 DB에 저장하지 않는 통합 동작
