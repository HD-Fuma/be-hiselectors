# 셀렉터스 콘텐츠 판별기 설계

## 1. 목적

SNS 게시물의 텍스트에서 셀렉터스 관련 증거를 추출해 다음 세 상태로 분류한다.

- `CONFIRMED`: 셀렉터스 콘텐츠임을 뒷받침하는 결정적 증거가 있음
- `REVIEW_REQUIRED`: 결정적 증거는 없지만 사람이 우선 검토할 만한 정황이 있음
- `NOT_SELECTORS`: 현재 텍스트만으로는 셀렉터스 관련 근거가 부족함

기존 수집 서비스와의 호환성을 위해 `isSelectorsContent(RawContent)`는 유지하며,
새 `classify(RawContent)` 결과가 `CONFIRMED`일 때만 `true`를 반환한다. DB 구조와 저장 정책은
이번 변경 범위에 포함하지 않는다.

## 2. 설계 원칙

1. 결정적 규칙과 추정 점수를 분리한다. 약한 신호 여러 개가 우연히 더해져 자동 확정되는 것을 막는다.
2. 본인 코드만 인정하지 않는다. 정상 형식의 다른 셀렉터스 코드도 관련 콘텐츠로 수집한다.
3. 더현대 공용 상품 URL만으로는 확정하지 않는다. 일반 상품 공유와 구분할 수 없기 때문이다.
4. 해시태그 규칙은 일반 문자열이 아니라 실제 `#해시태그` 토큰에만 적용한다.
5. 판정 결과에 점수와 근거를 함께 반환해 결과를 설명하고 규칙을 재현할 수 있게 한다.
6. 판별 규칙 버전을 결과에 포함해 향후 규칙 변경을 추적할 수 있게 한다.

## 3. 판정 흐름

### 3.1 텍스트 정규화

- `RawContent.texts`를 줄바꿈으로 결합한 값을 사용한다.
- Unicode NFKC 정규화를 적용한다.
- URL 호스트와 영문 키워드는 대소문자를 구분하지 않는다.
- URL은 텍스트에서 추출한 뒤 URI로 파싱하여 호스트를 정확히 비교한다.
- 후행 문장부호는 URL에서 제거한다.
- 해시태그는 `#` 뒤의 한글·영문·숫자·밑줄 토큰으로 추출한다.

### 3.2 결정적 확정 규칙

다음 중 하나라도 충족하면 `CONFIRMED`다.

1. 정상 형식 레퍼럴 코드가 본문에 존재한다.
   - 초기 형식: 대소문자 무시 `RC` + 숫자 9자리 + `T`
   - 예: `RC000005105T`
   - 다른 셀렉터의 코드도 인정한다.
   - URL 인코딩되거나 형식이 깨진 코드는 인정하지 않는다.
2. 정확한 `hi.thehyundai.com` 상품 URL의 `ptrsRefCd` 쿼리 값이 정상 레퍼럴 코드다.
3. 정확한 `hi.thehyundai.com` 호스트의 셀렉터스 전용 경로다.
   - `/sellectors/manage/shop/...`
   - `/sellectors/{샵 또는 그룹 식별자}`
4. 실제 해시태그 중 `%더현대%` 토큰과 정확한 `#셀렉터스` 토큰이 각각 존재한다.
   - `#더현대서울 #셀렉터스`: 확정
   - `#더현대 #셀렉터스`: 확정
   - `#더현대서울`: 미확정
   - `#셀렉터스`: 미확정
   - 일반 문장 `더현대 셀렉터스`: 미확정
   - 단일 태그 `#더현대셀렉터스`: 미확정

공용 상품 URL `/product/{상품번호}`는 레퍼럴 코드가 없으면 확정 근거가 아니다.

### 3.3 검토 점수

결정적 규칙이 없을 때만 다음 점수를 합산한다.

| 근거 | 점수 | 비고 |
| --- | ---: | --- |
| 셀렉터스 또는 더현대 셀렉터스 명시 | +4 | 해시태그 결합 확정 조건과 별개 |
| 셀렉터스샵·셀렉터스 샵 명시 | +4 | 일반 셀렉터스 명칭과 중복 가산하지 않음 |
| 코드 없는 더현대 공용 상품 URL | +3 | URL만으로 확정 금지 |
| 셀렉터스 샵 등록 상품명 일치 | +2 | 상품 카탈로그 컨텍스트가 도입될 때 적용 |
| 경제적 이해관계 표시 | +1 | 광고·협찬·제휴·판매수수료 등 |
| 구매 전환 문구 | +1 | 프로필 링크·구매·주문·쿠폰 등 |
| 더현대 언급 또는 관련 해시태그 | +1 | 단독으로 검토 대상이 되지 않음 |
| 승인된 대행사 계정 태그 | +1 | 승인 목록 컨텍스트가 도입될 때 적용 |

- 6점 이상: 강한 검토 후보
- 3~5점: 일반 검토 후보
- 0~2점: 비대상

두 검토 구간은 모두 `REVIEW_REQUIRED`로 반환하고, 점수로 우선순위를 구분한다. 초기 버전에서는
검토 점수만으로 `CONFIRMED`에 승격하지 않는다.

현재 `RawContent`가 상품 카탈로그와 승인 대행사 목록을 제공하지 않으므로 해당 두 항목은 점수 정의에
남기되 이번 구현에서는 비활성화한다. 데이터 계약을 먼저 추가하지 않고 DB를 조회하는 의존성을
분류기에 넣지 않는다.

## 4. 반환 모델

`SelectorsContentClassification`은 다음 정보를 가진 불변 값 객체다.

- `decision`: `CONFIRMED`, `REVIEW_REQUIRED`, `NOT_SELECTORS`
- `score`: 결정적 규칙을 제외한 검토 점수
- `reviewTier`: `STRONG`, `NORMAL`, `NONE`
- `evidence`: 탐지된 근거 enum 집합
- `referralCodes`: 탐지한 정상 레퍼럴 코드 집합
- `matchedUrls`: 판정에 사용한 URL 집합
- `ruleVersion`: 초기값 `selectors-text-v1`

`isSelectorsContent`는 `classification.decision() == CONFIRMED`의 호환용 래퍼다.

## 5. 오류와 경계 처리

- `RawContent`가 `null`이면 명확한 `IllegalArgumentException`을 던진다.
- 빈 텍스트는 `NOT_SELECTORS`, 0점으로 반환한다.
- 악성 유사 호스트(`evilhi.thehyundai.com`)는 인정하지 않는다.
- URL 인코딩으로 코드 형식을 우회한 값은 인정하지 않는다.
- 같은 근거가 여러 번 반복돼도 한 번만 점수를 부여한다.
- 같은 레퍼럴 코드나 URL은 결과에서 중복 제거한다.
- 결과 집합은 외부에서 변경할 수 없게 복사한다.

## 6. 데이터 근거

2026-08-18 안전 수집 표본 1,439건에 초기 탐지식을 적용한 결과다.

| 신호 | 건수 | 비율 |
| --- | ---: | ---: |
| 정상 형식 레퍼럴 코드 | 1 | 0.07% |
| 셀렉터스 전용 경로 | 1 | 0.07% |
| 셀렉터스·Selectors 명칭 | 4 | 0.28% |
| 더현대 언급 | 54 | 3.75% |
| 광고·협찬·제휴 표시 | 474 | 32.94% |
| 구매 전환 문구 | 174 | 12.09% |

결정적 규칙의 합집합은 1건이었다. 광고·협찬 표시는 약 3분의 1에서 발견되어 단독 확정 근거로
사용하기 어렵다. 이 결과는 사용자 제공 태그 계정 58개의 첫 페이지 표본이므로 전체 모집단 비율로
일반화하지 않는다.

## 7. 신뢰도 및 임계값 검증

사람 라벨의 재현성과 알고리즘 성능을 분리해 평가한다.

1. 현재 500건 표본을 점수 구간별로 층화하고, 결정적 규칙 표본은 전수 포함한다.
2. 두 판정자가 독립적으로 `해당/비해당`과 근거를 기록한다.
3. 두 명이면 Cohen's kappa, 세 명 이상 또는 결측 허용이면 Krippendorff's alpha를 계산한다.
4. `κ 또는 α >= 0.8`일 때 코드북이 안정적이라고 본다. 미달이면 불일치 항목을 분석해 정의를
   고치고 새 검증 표본으로 다시 측정한다.
5. 합의된 정답과 분류 결과는 정밀도, 재현율, F1, 혼동행렬로 평가한다.
6. 점수 임계값 후보 3~8점을 층화 교차검증 또는 부트스트랩으로 비교한다. 클래스 불균형 때문에
   정확도만 사용하지 않는다.

`0.8`은 콘텐츠 점수 임계값이 아니라 판정자 간 신뢰도 기준이다.

## 8. 타사 운영 방식에서 얻는 원칙

- Amazon Associates는 Associate ID와 Tracking ID가 포함된 특별 링크로 유입과 성과를 연결한다.
- 네이버 브랜드 커넥트는 활동 채널 인증과 상품별 전용 링크 발급을 중심으로 운영한다.
- YouTube Shopping은 플랫폼 내부 상품 태그와 분석 데이터를 관리한다.
- impact.com은 캠페인 과업, 제출 콘텐츠, 추적 링크와 전환 데이터를 연결한다.

공통점은 자유 텍스트보다 플랫폼이 발급하거나 관리하는 식별자를 강한 근거로 사용한다는 것이다.
따라서 셀렉터스도 레퍼럴 코드·전용 경로를 최우선으로 보고, 일반 문구는 검토 점수로만 사용한다.

## 9. 별도 후속 범위

다음 항목은 셀렉터스 관련 여부와 독립된 판정 축으로 분리한다.

- 광고 표기 준수 여부
- 영상 최소 길이
- 욕설·유해 표현
- 이미지·영상·음성에만 존재하는 표시
- 게시물 텍스트 변경 해시 및 미디어 개수·식별자 변경
- 클릭·구매 전환과 게시물·상품의 추적 ID 연결

위반 여부가 셀렉터스 관련 여부를 바꾸지는 않는다. 먼저 관련 콘텐츠를 식별한 후 별도의 위반 검사기가
진단해야 한다.

## 10. 테스트 범위

- 정상·다른 사람 레퍼럴 코드 단독 확정
- 형식이 깨진 코드와 URL 인코딩 코드 거부
- 추천 코드가 있는 공용 상품 URL 확정
- 추천 코드 없는 공용 상품 URL은 검토 후보
- 전용 샵·그룹 URL 확정
- 정확한 호스트 경계와 유사 호스트 거부
- 두 종류 해시태그 동시 존재 확정
- 일반 문장, 한쪽 해시태그, 단일 결합 해시태그는 미확정
- 중복 신호 단일 가산
- 검토 점수 경계 2·3·5·6점
- 빈 텍스트, 여러 텍스트 분산 신호, 대소문자 및 Unicode 정규화
- 기존 `isSelectorsContent`의 확정 전용 하위 호환
